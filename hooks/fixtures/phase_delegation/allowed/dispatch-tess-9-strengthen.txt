## A. The two verbs, and the contracts that must not change

### `autopilot select` (`cli/__main__.py` `_run_select`)

Invoked as `python3 cli/__main__.py select [--prds PATH]`.

- Prints ONE JSON line: `{"prd": <basename|null>, "source": "wip"|"backlog"|"drained", "skipped": [...]}`.
- The JSON line is printed BEFORE any state write, so a failed skip write never swallows the pick.
- Each entry of `skipped` has exactly the keys `prd`, `command`, `exit_code`, `note`, `at`. The `at` value is an ISO-8601 UTC stamp (`...Z`). **The `at` key is the verb's own addition - the shared helper does not produce it.**
- A skipped candidate stays in `backlog/` on disk. It is dropped from THIS pick only.
- `wip/` candidates are never eligibility-gated.
- Exit 0 in every case INCLUDING `drained`. The only non-zero exit is 2, when `skipped` is non-empty AND the state file exists AND appending to `state.batch.skips[]` fails.
- When `skipped` is non-empty and there is NO state file, nothing is written and the exit is 0.
- Skips are appended under `state.batch.skips[]`, not at the top level.
- With no `--prds`, the prds dir is the autopilot dir's sibling `prds`; with `--prds PATH` it is `PATH` verbatim.

### `autopilot frontmatter` (`cli/__main__.py` `_run_frontmatter`)

Invoked as `python3 cli/__main__.py frontmatter --prd PATH [--state PATH]`.

Its exit-code PRECEDENCE is load-bearing and currently untested. Pin it:

1. An unreadable/missing `--prd` exits **1** with `autopilot: cannot read PRD <path>: <err>` on stderr. **This check happens before the state file is looked at at all** - so an unreadable PRD plus a future-schema `state.json` still exits 1, not 6.
2. A future `schema_version` in state exits **6**, refusing before any write.
3. A failed state write exits **2** with `autopilot: frontmatter write failed: <err>` on stderr.
4. Success exits **0** and prints ONE JSON line of the applied fields, `sort_keys=True`.

Its stderr ORDERING is also load-bearing:

- Parse warnings and the lane warning print **before** the state write. Pin the consequence that actually matters: **when the write fails (exit 2), the parse/lane warnings have still been printed.** A refactor that collects warnings and prints them only on success would lose them, and that is the regression this test exists to catch.
- The `autopilot: PRD frontmatter reset <key> <old> -> <new>` lines print **after** a successful write, one per field whose value actually changed. They never print on a failed write (there was no reset).
- An invalid `lane:` value earns exactly this warning: `autopilot: PRD frontmatter lane=<value!r> is not one of solo/fast-track/full; defaulting to <verdict>`. An ABSENT `lane:` key earns silence.

**C1. `select_eligible` takes ONE argument and derives the project root itself.**
New signature: `select_eligible(prds_dir)` -> `(basename, source, skips)`. The eligibility command's working directory is derived from `prds_dir` alone. The derivation: resolve `prds_dir`; if it has more than 3 parents use `parents[3]`, otherwise use the resolved `prds_dir` itself. (For the standard `<root>/docs/dev/project-management/prds` that yields `<root>`; for a shallow `--prds /prds` it yields the prds dir, so a misconfigured flag costs a failed check and not a traceback.)

Why it changes: two callers derived that directory two different ways, so the same PRD's eligibility check could run from two different directories. The `--prds`-honouring derivation wins, because honouring the override is the flag's whole purpose.

Pin: with a NON-STANDARD `prds_dir`, the eligibility command runs from the directory that derivation names. Use an eligibility command that reveals its own cwd - for example one that succeeds only when a marker file is present in the expected directory - so the test measures where the command ran, not merely that it ran.

**C2. `frontmatter.apply` gains an `on_warning` callback and returns the reset lines.**
New signature: `apply(prd_path, state_path, *, on_warning=None)` -> `(fields, warnings, resets)`.
- `on_warning`, when given, is called with each warning line BEFORE the state write. This is what lets the verb keep printing warnings on the failed-write path.
- `resets` is the list of `autopilot: PRD frontmatter reset <key> <old> -> <new>` lines, computed from the pre-write state, and is `[]` when nothing changed and on any failure.
- `warnings` keeps its current content (parse warnings plus the lane warning). The reset lines are a SEPARATE return value, not appended to it.

**C3. `enter`'s returned warnings now include the reset lines.**
`autopilot enter`'s JSON-adjacent warning list (the one the verb prints to stderr after its JSON line) must carry the reset lines too. Today the reset diagnostics exist only inside the `frontmatter` verb, so a session entering through `enter` never sees that a PRD's frontmatter overwrote a state field. Pin it at the LIBRARY level if the CLI-level assertion belongs to a test file you may not edit: `enter()`'s returned `warnings` must contain a reset line when the PRD's frontmatter changes a field that state already held with a different value.

**C4. `selection.py`'s module docstring must stop making two false claims.**
- It says `select_eligible` is "the I/O-owning core shared by `autopilot select` and `autopilot enter`". That is false today (only `enter` calls it) and must be true after the refactor.
- It says the module is `PURE: takes directory LISTINGS, never paths`, which `select_eligible` and its `from cli import eligibility` already break.

Pin: the docstring must not claim unqualified purity - the word `PURE` may survive only if the same docstring also names the exception. Assert on the docstring text (`selection.__doc__`), not on a comment.
