Six deferred findings on the wave verbs (00214-00217), each reproduced at HEAD:
1. 00221: `test_wave_assemble_summary.py` not wired into `dev/bin/release-checks` `[checks] waves` block nor `test_wave_docs.py`'s `_WAVE_TEST_FILES`.
2. 00222: `wave_assemble.py` `_drain_lane`/`_assemble_lane` mutate lane state in memory; the single `save()` runs AFTER `git worktree remove` and `branch -D` — a crash in that window loses state. Need `save()` before the destructive git ops, and `worktree_removed` saved right after remove succeeds. `wave_cli.run` should catch `OSError` from assemble, print one `autopilot:` line, exit 1.
3. 00225: `wave_review.py:403` uses raw `git status --porcelain` in the assembly worktree instead of `store_tree.foreign_dirty`. Also: when review seeds the assembly worktree, every `prds/backlog/*.md` there must move to `prds/hold/` (committed on the assembly branch) before the nested loop spawns, so the nested loop can't pick up main-checkout backlog PRDs.
4. 00226: `wave_review.py:483` `_land_review_failed` always returns 4, even after an operator hand-moved the stub to the assembly worktree's `prds/done/`. Needs to check for that and, if present, set status to `converged` (saved) and continue the normal land path.
5. 00227: `wave_slots.py:108-116` `_discard` renames a stale slot aside before judging it, without a lock — race lets two holders claim the same slot. Fix: per-slot `fcntl.flock(LOCK_EX)` sibling lock file `N.lock`, held by `_claim`, `_discard`, and `release` across their whole check-and-rename; `release` verifies pid ownership before removing.
6. 00239: `loop.py:506` `_record_review_once_store` calls `record_store` without the `store_tree.in_wave_lane(self.env)` guard that `loop.py:611` and `loop_act.py:218` already have.
