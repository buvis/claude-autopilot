Source: ddb refactor assessment `/Users/bob/git/src/github.com/doogat/ddb/dev/local/audit-results/refactor-assessment-2026-09-06.md` (F2, F7, Decision step 3) and the ddb batch ledgers under `/Users/bob/git/src/github.com/doogat/ddb/dev/local/` (read-only evidence: `reports/` and `deferred/` paths below sit under its `autopilot/`, `prds/done/` paths beside it).

## Problem

The loop already has one plan-time gate, F5: `cli/policy.py:24` sets `LOOP_TASK_CEILING = 15`, `plan_over_ceiling` (`policy.py:27-33`) counts `state.tasks`, `autopilot check-plan` (`cli/__main__.py:354-378`) exits 3 above it, and `plan-tasks/SKILL.md:362-386` step 5.5 stalls the PRD in loop mode with site `oversized_plan`. The per-task budget in step 4.6 (`SKILL.md:196`, `:220-234`) stalls only when ONE task cannot be split under 150K. Neither gate sees a plan that has outgrown its PRD. ddb 00167 declared 4 task lines (`prds/done/00167-...md:74-91`) and one file, `ddb-core/src/sync_manager/mod.rs` (`:44-45`), and was planned into 21 tasks (`reports/202607161128-report.md:277`) touching parser, id_minting, types and git_ops (assessment `:65`); it took 28 sessions and $345.26 (`report.md:303-305`), 18 cycle-1 and 27 cycle-2 findings (`:286-287`), and exited at the cap with 3 HIGH deferred (`deferred/202607161128-deferred.json:26-54`). 00169 declared 10 task lines (`00169-...md:161-184`) across nine tree directories (`:95-113`), planned into ~20 tasks (assessment `:65`, "5-11 to 15-21"; the report's `Tasks: 0/0` at `:335` is the cleared tracker), and cost $431.18 over 13 sessions (`report.md:363-365`), the batch's most expensive PRD. Across the batch the plan-time expansion was 2.2x, range 1.2x to 5.25x (assessment `:121`); the operator's own 2026-08-16 measurement attributes August cost to PRD size (`~/.claude/projects/-Users-bob--claude/memory/project_autopilot_prd_size_drives_throughput.md:25-28`). The assessment's Decision step 3 (`:157`) asks the autopilot plugin for "a plan-time size gate (~12-15 tasks or the PRD's declared modules)". Neighbours cover none of this: discovery 00157 (per-task review skips, tier routing, codex hooks) and 00177 (Bob's retry, the Devon cap, codex stdin) never touch plan size; backlog 00179-00187 are review-effort, dispatch and cap-out fixes; 00188 only records `planned` against PRD task lines in the convergence row after the run (a measurement, not a gate); `work/references/task-splitting.md:9-29` splits at dispatch time, after the plan is already committed to. This PRD adds only the delta over F5: an expansion ratio, a module-drift check against the PRD's Repository Structure tree, one machine-written split note, one override key, and one stall site for all three rules.

## Solution

Extend the pure policy and the `check-plan` verb rather than add a second gate. After planning and before Phase 3, `plan_expansion(state, prd_text)` in `cli/policy.py` computes `planned` (task count from the snapshot, as today), `expansion = planned / prd_task_lines`, and `drift` (directories of planned files that the PRD's Repository Structure tree never names). It stalls when `planned > 15`, or `expansion > 3.0` with `planned > 8`, or `len(drift) >= 2`. `check-plan` gains a required `--prd` flag, writes a split note grouped by module on every stall verdict, and prints the stall instruction with site `plan_expansion` (this codebase records a stall as the deferred record's `site` slug, `references/recovery.md:11-19`; that slug is what the settled decision calls the stall reason). PRD frontmatter `plan_expansion: allow` skips the check. Planned files come from a new `files` key each task payload carries, the same slice step 4.7 already writes to the per-task `plan-<n>-files.txt` under the tmp dir (`SKILL.md:255`), persisted beside the other top-level keys step 4 lists (`SKILL.md:75`). Thresholds live in `policy.py` alone, pinned by contract tests; the prose pin lives beside the other plan-tasks prose tests.

## Requirements

### Must have
- `cli/policy.py` exports `EXPANSION_RATIO_MAX = 3.0`, `EXPANSION_MIN_TASKS = 8`, `MODULE_DRIFT_MAX = 1`, `PLAN_EXPANSION_OVERRIDE_KEY = "plan_expansion"`, and `plan_expansion(state, prd_text, ceiling=LOOP_TASK_CEILING) -> Verdict`; `LOOP_TASK_CEILING` and `plan_over_ceiling` stay as they are.
- `Verdict` is a frozen dataclass: `stall: bool`, `reasons: tuple[str, ...]` drawn from `("task_count", "expansion", "module_drift")`, `planned: int`, `prd_tasks: int`, `expansion: float | None`, `drift: tuple[str, ...]` (sorted), `unfiled: int` (tasks with a missing or empty `files` list), `override: bool`, `note: str`.
- `prd_tasks` counts lines matching `^- \[[ x]\]` in `prd_text`. When it is 0, `expansion` is `None` and the expansion rule is skipped.
- PRD modules come from the fenced block under `### Repository Structure`: each line's full path is rebuilt from the tree glyphs (`├──`, `└──`, `│`; a line with no glyph prefix is a root entry; a name ending in `/` is a directory; a glyph line belongs to the nearest preceding directory at a lesser depth, depth being the count of 4-character glyph columns). Rebuild directory ancestry including parents implicit in slash-separated paths. Only leaf directory modules (directories with no listed descendant directory) grant recursive subtree coverage; grouping parents do not grant it. A file explicitly listed directly under a grouping parent, or at repository root, is allowed individually without allowing its siblings. Thus `src/` containing `auth/`, `billing/` and `main.py` permits those leaf subtrees and `src/main.py`, but not `src/payments/a.py` or `src/other.py`. Never infer blanket `.` coverage from a root-level file. The module of an unlisted task file is its parent directory; drift is the sorted distinct set of those directories. When the PRD has no such block, skip only the drift rule and say so in both the note and CLI diagnostics.
- Task modules come from each `state.tasks[i].files` list (repo-relative paths). A task with a missing or empty `files` list contributes no modules, is counted in `unfiled`, and is listed in the note under `(no files declared)` so a planner who omits the key is visible, never silently exempt.
- Missing/empty file lists and a skipped drift check are visible even on success: `check-plan` emits `plan-expansion: unfiled=<n>; drift=checked|skipped (no Repository Structure)` to stderr when `unfiled > 0` or drift was skipped. Under override combine this information with its single diagnostic line. These are diagnostics, not additional stall rules. Keep the split-note file restricted to stall verdicts.
- The note is Markdown: a title naming the PRD, one line with `planned`, `prd_tasks`, `expansion` and the reasons, then one `## <module>` section per module, each marked `listed` or `UNLISTED`, each holding `- <task id> <task name>` lines with that task's files in the module. A task spanning several modules appears under each.
- `plan_expansion: allow` in the PRD frontmatter (parsed by `cli/frontmatter.py`, opt-in at that exact value like `design_gate: user`, `frontmatter.py:53-56`) sets `override=True`, `stall=False`, `reasons=()`; the note is still built. When an operator intentionally admits an oversized plan, planner/recovery guidance tells them to set `rework_cap: 3` explicitly alongside `plan_expansion: allow` before unattended resume. Neither this gate nor the frontmatter parser changes the cap automatically.
- `autopilot check-plan --state S --prd P [--ceiling N]`: `--prd` required (argparse usage error without it); exit 0 under every rule; exit 3 on stall, having written the note to `<state dir>/split-notes/<prd-stem>.md` (directory created as needed) and printed to stderr the reasons with their numbers, the note path, and `Loop mode: stall this PRD (site "plan_expansion", detail "<reasons>; note <path>"). Interactive: this is a warning, continue.`; exit 0 with one stderr line naming the skipped rules when the override is set; exit 2 on unreadable state or PRD, as today for state.
- `plan-tasks/SKILL.md` step 4 lists `files` among the top-level payload keys (the expected implementor-writable paths, identical to the step-4.7 file slice), both worked payloads in step 4.7 carry `"files": [...]`, and step 5.5 passes `--prd dev/local/prds/wip/<state.prd>`, names the three rules with their numbers, the site `plan_expansion`, the note path, and the override key in one line.
- `references/recovery.md` and `references/state-schema.md` document `plan_expansion` as the single site for this gate; `oversized_plan` is named once as the legacy spelling on records written before this PRD.
- CHANGELOG entries under `[Unreleased]`: `**plan-tasks**` (Added) for the gate and the `files` key; `**run-autopilot**` (Changed) for `check-plan --prd`, the note, and the site rename.

### Nice to have

## Implementation

### Module: policy
- **Location**: `skills/run-autopilot/cli/policy.py`, `skills/run-autopilot/cli/test_policy.py`
- **Responsibility**: the thresholds, the PRD-tree parse, the decision, the note text. PURE: no disk, no state writes.
- **Exports**: `EXPANSION_RATIO_MAX`, `EXPANSION_MIN_TASKS`, `MODULE_DRIFT_MAX`, `PLAN_EXPANSION_OVERRIDE_KEY`, `Verdict`, `prd_task_lines(prd_text)`, `prd_modules(prd_text)`, `plan_expansion(state, prd_text, ceiling=LOOP_TASK_CEILING)`

### Module: frontmatter
- **Location**: `skills/run-autopilot/cli/frontmatter.py`, `skills/run-autopilot/cli/test_frontmatter.py`
- **Responsibility**: recognizes the opt-in `plan_expansion: allow` as state field `plan_expansion_override: true` (an unknown top-level key passes `schema.validate`, `cli/schema.py:156-185`, so no schema edit).
- **Exports**: `parse(text)` unchanged in signature

### Module: check-plan
- **Location**: `skills/run-autopilot/cli/__main__.py` (`_add_check_plan`, `_run_check_plan`, docstring lines 26-27)
- **Responsibility**: read state and PRD, call `plan_expansion`, write the note, map the verdict to the exit contract.
- **Exports**: the `check-plan` subcommand

### Module: plan-tasks prose
- **Location**: `skills/plan-tasks/SKILL.md` steps 4, 4.7, 5.5; `skills/plan-tasks/scripts/test_plan_size_gate_prose.py`; `dev/bin/release-checks`
- **Responsibility**: the planner persists `files` and runs the gate with `--prd`; the numbers cannot drift without a red test.
- **Exports**: none (skill prose)

### Module: reference docs
- **Location**: `skills/run-autopilot/references/recovery.md`, `skills/run-autopilot/references/state-schema.md`, `CHANGELOG.md`
- **Responsibility**: document the override, site migration and CLI contract
- **Exports**: none (documentation)
