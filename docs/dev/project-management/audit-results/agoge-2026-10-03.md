### 1 of 24 - HIGH - A git alias pushes past the "critical finding" push block

**What:** The `guard_push_on_critical.py` hook should stop any push while a critical review finding is open on the branch. It only spots the literal word `push`, so a push through a git alias or a script goes through. Found by trudy (security).

**Evidence:** With a pending `critical-on-master` marker, `git push` exit 2 (blocked), but `git -c alias.p=push p` exit 0. Running that form for real landed commit `a9d0b45` on the fixture's bare remote. `git send-pack`, `git submodule foreach git push`, and `python3 -c "os.system('git push')"` also exit 0. Confirmed.

**If unchanged:** an agent working around a block (or a model that knows aliases) can push code that carries an open CRITICAL finding. Likelihood is low per session but compounds across unattended batches. It breaks the hook's own promise to "err toward a false deny, never a false allow".

**Options:**
1. **(Recommended) Treat unknown subcommands and `-c alias.*` as uncertain.** Add `send-pack` as a push, and add `python`, `python3`, `perl`, `node`, `ruby` and `osascript` to `_PUSH_CAPABLE`. Benefit: closes every case trudy ran except an alias set in an earlier command. Drawback: more false denies on rare commands. Effort S. Could break: legitimate scripted git calls during a custody block get denied.
2. **Also resolve aliases** with `git config --get alias.<sub>` in the target repo. Benefit: also catches `git config alias.pp push; git pp`. Drawback: one more git spawn per call (see finding 16). Effort M. Could break: hook latency.
3. **Enforce server-side:** a local `pre-push` git hook installed while custody is pending. Benefit: catches every client-side route. Drawback: install/remove lifecycle, repo config edits. Effort L. Could break: users' own pre-push hooks.
4. Accept or defer.

**Against the recommendation:** text matching can never be complete. Option 1 narrows the gap but does not close it.
