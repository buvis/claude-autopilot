## 1 of 14 - MEDIUM - Widened verbs refuse ordinary per-task prompts

**What.** PRD 00267 added six verbs (`start do perform complete launch call`) to the guard that stops a build session handing a whole phase to a subagent. A task prompt that merely mentions a phase or a skill name, such as "Complete the planning phase notes" sent to Ivan, is now refused. Found by walter (journeys) and wendy (release truth).

**Evidence (confirmed).** 12 of 13 synthetic per-task prompts: checkout guard exit 2, 0.9.0 exit 0, e.g. `[autopilot:ivan] "Complete the planning phase notes in …/plans/00300.md; task 3 only."`, `"Call the plan-tasks helper script with --dry-run"`, `"Do design-solution/references/x.md first"`. Questions too: `"Do the work phase tests pass on this branch?"` exit 2. A real product line (`phase-build.md:360`, "…every `task-add` call `/autopilot:plan-tasks` made…") quoted in an Ivan edit prompt is newly refused. CHANGELOG.md:13 promises "ordinary prose about a phase stays allowed". Replay of 1129 real dispatches found no newly refused per-task prompt, so the rate today is unproven.

**If unchanged.** Once 00267 ships, any Ivan, Tess or worker call that mentions a phase gets a hard refusal mid-build, and the session has to guess how to rephrase (see 2). Likelihood: low per call, but it rises as prompts quote skill prose. Stays stable.

**Options.**
1. **(Recommended) Anchor the widened verbs to the object position.** Require end of clause or `for PRD|for task` after the phase name for the six new verbs, and add a trailing boundary `(?![-/.\w])` to the bare-skill form. Benefit: kills the whole false-positive class, keeps the 00267 catches. Drawback: may reopen some phrasings 00267 meant to catch. Effort M. Could break: the 18 denied fixtures (rerun them). Strongest reason against: the regex gets more complex, and the guard is already hard to reason about.
2. **Keep bare skill names on the six original verbs only, and add allowed fixtures for the observed cases.** Benefit: small and targeted. Drawback: question forms ("Do the work phase tests pass?") are still refused. Effort S. Could break: little.
3. **Reword the CHANGELOG to state the real scope.** Benefit: honest docs, no code risk. Drawback: the refusals stay. Effort S.
4. Accept or defer.

**What.** Many plain ways to hand over a phase are allowed by both the checkout and the 0.9.0 guard. Found by trudy and wendy; wendy also shows the CHANGELOG's "up to three determiner words" and "quoted skill names" over-promise.

**Evidence (confirmed).** Allowed by both (exit 0/0): `Run your work phase for PRD 00300 now.`, `Kick off the work phase for PRD 00300 and finish every task.`, `Run the work-phase for PRD 00300.`, `/autopilot:work docs/dev/project-management/prds/wip/00300.md`, `Run “/autopilot:work” now.`. Control `Run the work phase…` -> 2/2.

**If unchanged.** A model under context pressure that writes one of these delegates the whole phase, which is the failure the guard exists for. These are phrasings a cooperative model plausibly writes. Stable.

Add denied fixtures per class.** Benefit: closes the realistic phrasings. Drawback: more verbs means more false positives (finding 1). Effort M. Could break: allowed fixtures. Strongest reason against: it repeats 00267's approach, a word list that keeps missing.
2. Swap the word lists for a structural check: refuse any Agent call to a non-exempt type whose prompt names a phase skill or phase and has no `task N` / `only` scoping. Benefit: catches the class, not the words. Drawback: a new design with its own false positives. Effort L.
3. Fix only the CHANGELOG wording (fixed word list, which quotes). Benefit: honest docs. Drawback: the gaps stay. Effort S.
4. Accept or defer.
