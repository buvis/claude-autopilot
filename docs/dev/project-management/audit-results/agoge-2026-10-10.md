## 1 of 20 - HIGH - In a repo that does not gitignore `docs/dev/tmp/`, the test gate never runs

**What.** The gate's dirty-tree check counts only `docs/dev/project-management/` as the store, while the rest of the product (`store_tree.STORE_PREFIXES`) also treats `docs/dev/tmp/` as scratch. Without a `docs/dev/tmp/` ignore rule, the product's own staged prompts and gate log make the tree look dirty. `review-stage` then prints "gate skipped" and exits 0, and `verify` refuses every run. Found by heidi (integration) and wendy (release).

**Evidence (confirmed).** Fixture with no `.gitignore` and `GIT_CONFIG_GLOBAL=/dev/null`: HEAD `review-stage` exit 0, `Tests: (gate skipped: working tree dirty outside the store)`. Its only dirt was `?? docs/dev/tmp/alice-prompt-1.md ... ?? docs/dev/tmp/gate-1.log`. The same fixture on 0.9.0 gives `Tests: 5 passed ... (suite run this cycle)`, so this is a regression. `verify` gives exit 1 `dirty: true` from its own log. `verify --log <repo>/gate.log` also dirties itself. This repo is shielded only by `.gitignore:7` and `~/.gitignore_global`. Nothing in the product writes the ignore rule.

**If unchanged.** Every other repo using the next release loses its test gate. The review shows a "skipped" line instead of counts, exits 0, and a red suite ships unnoticed. The chance is high for any repo without a global ignore. It stays stable but hits every cycle.

**Options.**
1. **(Recommended) Make `_dirty_outside_store` use the same prefix set as `store_tree` (store plus `docs/dev/tmp/`), and always exclude the run's own `log_path`.** Benefit: one definition of "store", and the gate runs anywhere. Drawback: product edits placed under `docs/dev/tmp/` go unseen (that tree is scratch by rule). Effort S. Could break: tests that expect `docs/dev/tmp` dirt to refuse. Strongest reason against: it widens what the check ignores, the opposite direction to packet 3.
2. Have `ensure-store` write a `docs/dev/tmp/` ignore entry into the repo's `.gitignore`. Benefit: no change to dirt semantics. Drawback: it edits a user file, and already-initialised repos stay broken until re-init. Effort S. Could break: repos that track something under `docs/dev/tmp`.
3. Make `review-stage` exit non-zero when it skips the gate for dirt. Benefit: the skip becomes loud everywhere. Drawback: the gate still never runs; this only reports it. Effort S. Pairs with 1.
4. Accept or defer.

Test: a fixture with no ignore and `GIT_CONFIG_GLOBAL=/dev/null`, where `verify` must give `recorded: true` and review-stage's Tests line must carry counts (`cli/test_verification_dirty.py`).
